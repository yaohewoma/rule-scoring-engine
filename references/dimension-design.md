# 维度设计指南

## 维度数量

建议 4~8 个维度。太少区分度不够，太多维护成本高。

## 维度命名

```python
SCORE_DIMS = [
    "functionality",    # 功能完整度
    "innovation",       # 创新性
    "ux",               # 交互体验
    "visual",           # 视觉设计
    "techDifficulty",   # 技术难度
    "practicality",     # 实用价值
]
```

## 典型场景 × 维度设计

### 作品评审
| 维度 | 权重 | 说明 |
|------|------|------|
| 功能完整度 | 20% | 功能是否齐全、是否能解决真实问题 |
| 创新性 | 25% | 是否有独特卖点、是否与竞品差异化 |
| 交互体验 | 15% | 操作是否流畅、界面是否友好 |
| 视觉设计 | 15% | 设计是否美观、风格是否统一 |
| 技术难度 | 15% | 技术实现复杂度、是否有技术亮点 |
| 实用价值 | 10% | 是否有实际应用场景、是否有用户 |

### 简历筛选
| 维度 | 权重 | 说明 |
|------|------|------|
| 经验匹配 | 30% | 工作年限、行业经验是否匹配 |
| 技能广度 | 25% | 技术栈覆盖范围 |
| 项目深度 | 20% | 项目复杂度、个人贡献 |
| 教育背景 | 10% | 学历、专业相关性 |
| 沟通表达 | 15% | 简历描述的清晰度、条理性 |

### 内容质量评估
| 维度 | 权重 | 说明 |
|------|------|------|
| 准确性 | 30% | 事实是否正确、引用是否可靠 |
| 深度 | 25% | 分析是否深入、是否有独特见解 |
| 可读性 | 20% | 结构是否清晰、语言是否流畅 |
| 完整性 | 15% | 是否覆盖了主题的所有关键点 |
| 时效性 | 10% | 内容是否最新、数据是否过时 |

## 设计原则

1. **互斥性**：维度之间不应重叠。如"创新性"和"技术难度"不要有交叉
2. **可量化**：每个维度都能找到对应的量化指标或关键词
3. **业务导向**：维度必须反映业务价值，不是技术分类
4. **权重明确**：如果用户有明确的优先级，定义权重；否则默认等权

### 权重实现

`full-engine.py` 的 `ScoringConfig.DIM_WEIGHTS` 已实现加权平均计算。各维度权重可在 `ScoringConfig` 中配置，默认值与上表一致。`score_project()` 使用加权平均替代等权平均：

```python
# ScoringConfig 中的默认权重
DIM_WEIGHTS: Dict[str, float] = {
    "functionality": 0.20,
    "innovation": 0.25,
    "ux": 0.15,
    "visual": 0.15,
    "techDifficulty": 0.15,
    "practicality": 0.10,
}

# score_project() 中加权平均
avg = round(sum(
    scores[d] * config.DIM_WEIGHTS.get(d, 1.0 / len(SCORE_DIMS))
    for d in SCORE_DIMS
), 1)
```
